## Receipt semantics

Only exact verified C009 when narration or overlay is required; otherwise exact C004, with no
authoritative master allowed. Candidate bytes remain Windows read-locked through QA/publication.
All upstream files are read-only. Changed provenance creates a new qa_input_digest directory.
Existing malformed/partial/extra/tampered receipts conflict, never overwrite. Exact restart rehashes
current candidate and provenance, verifies receipt_digest and skips probe/decode. Identity excludes
paths, text and verification time. Receipt is a local deterministic integrity record, not a signed
attestation against an adversary able to replace all authorities and recompute their hashes.

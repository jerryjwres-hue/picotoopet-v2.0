## 2. 各模型的 Prompt 方法(上游依据)

### 2.1 Wan2.2 TI2V-5B(生产路径)
- 上游 README 没有给 T2V 的提示词模板,只有描述性长句示例;**推荐开启 prompt extension**(DashScope `qwen-plus` 或本地 Qwen2.5-3B/7B/14B-Instruct)以丰富细节。I2V:"可仅凭输入图生成,提示词可为空(配合 extension)";I2V extension 用 `qwen-vl-max` 或 Qwen2.5-VL。
- TI2V-5B:README 称支持 **720P、24 FPS**,尺寸 `1280*704` 或 `704*1280`;帧数与最大时长**页面未写明**(UNVERIFIED);"5 秒 720P 在单张消费级 GPU 上 9 分钟内"是速度数据,不是时长上限。
- **本项目现状(代码事实):** 输出档 832×480 / 480×832 / 640×640,24 fps,最多 121 帧(≈5 秒),`4n+1`。上游宣称的 720P 与本项目档位不同——**这是否影响第一轮良品率没有证据,只能作为 A/B 假设**(§4 的 A3,需要 G006/用户批准改档位,本协议不做)。
- 对我们有效的 Prompt 方法(与 `wan22-shot-prompt-v1.1.0` 一致):主体身份 + **一个**可见动作 + 场景 + 景别/运镜 + 光线;短镜头单一主运动;身份短语每镜头逐字重复;不堆"8K/masterpiece/cinematic"。负向概念只是建议,真正的负向提示词由 `wan22.safe-negative.v1` 决定。

### 2.2 Wan2.1 VACE(仅评测)
- 输入:文本 + `src_video` / `src_mask` / `src_ref_images`;任务为 R2V(参考生成)、V2V、MV2V。
- 模型:Wan2.1-VACE-1.3B 约 81×480×832;14B 约 81×720×1280。许可:Wan2.1 系列标 Apache-2.0,LTX 系标 RAIL-M,"继承原模型许可"。
- 提示词:页面写明英文 Wan2.1 与 LTX 需要 prompt extension;**编辑类任务扩写可能与源视频不匹配**。
- 对我们的意义:R2V 理论上是"跨镜头锁定同一只宠物"的更强手段,但它需要参考图(= 需要 Core 持有已验证参考资产),并且需要新 workflow 与模型权重——**均未验证,当前不可执行**。

### 2.3 HunyuanVideo-1.5(仅评测)
- 提示词:页面建议**更长更细**的提示词;`--rewrite` 默认开启,依赖 vLLM 兼容端点(推荐 Qwen3-235B 系),无端点则不重写。
- 分辨率 480p/720p(1080p 需超分);`--video_length` 默认 121;显存最低 **14 GB(开启 offload)**;第三方称 6 GB 未经项目验证。
- **许可条款:检索内容未包含条款原文,地域/商用限制 = UNVERIFIED**,必须读 LICENSE 原文后才能评估。
- 重写依赖 235B 级外部模型,与本项目"本地、无外部调用"的边界冲突,必须先过安全评审。

### 2.4 LTX-Video(仅评测)
- 提示词:**单段连贯的时间顺序描述**,以动作开头,字面、精确,**≤200 词**;推荐顺序:主要动作 → 动作/手势 → 角色与物体外观 → 背景 → 机位与运镜 → 光线与色彩 → 突变。
- 约束:分辨率可被 32 整除,帧数 `8n+1`(例 257);1216×704@30fps 为 2025-04 版默认;完整模型显存要求未给数字(UNVERIFIED)。
- 许可:仓库标 Apache-2.0,但 v0.9.5 权重另有 OpenRAIL-M 说明;逐权重许可 UNVERIFIED。

## 4. Prompt A/B 实验协议(需要真实帧,当前 UNVERIFIED)

**目的:** 回答"Video Bible 展开的提示词是否提高第一轮良品率",而不是挑选模型。

**固定项:** 模型/workflow(Wan2.2 T2V)、输出档、帧数、负向策略、步数/cfg/采样器、旁白与字幕、评审者与评审工具。
**自变量(每次只改一个):**

| 臂 | 内容 | 状态 |
|---|---|---|
| A0 | 现状:无 Bible,LLM 自由生成镜头文字 | 基线 |
| A1 | Bible 展开(`expand_shot_fields` + brief notes) | 本合同对象 |
| A2 | A1 + 动作拆分更严格(单镜头仅一个主运动) | 可选 |
| A3 | A1 + 更高输出档(接近上游 720P) | 需 G006/用户批准,本协议不执行 |
| A4 | 提示词句序(动作靠前 vs 场景靠前) | 可选,低优先 |

**单位与随机化:** 以"镜头"为单位;每个样例脚本在各臂各生成相同数量镜头;seed 由 `production_job_id|shot_id|profile` 派生,不同臂使用不同 job 因而 seed 不同,**不得声称同 seed 对比**。
**盲评:** 评审者只看到 `output_sha256` 与匿名编号,不知道臂;每个镜头按 #105 的 S01–S07 打 `ACCEPT / REVIEW / REGENERATE / BLOCKED`;整片按 V01–V06。
**主指标:** 镜头级"第一轮 ACCEPT 率"(分母 = 已完成渲染的镜头,`NeedsHuman` 单独报告);
**次要指标:** 每个被接受镜头的 GPU 墙钟秒(#105 `yield_metrics.sql` 的上界口径)、`SHOT_FIELD_DRIFT` 触发率、REVIEW 率、人工评审耗时。
**样本量与结论规则(必须预先登记):** 样本太小时只报告原始计数与 Wilson 区间,**禁止**"提升了 X%"式表述;任一臂 ACCEPT 数 < 预先登记的下限则结论为"无结论"。
**停止规则:** 任何一次出现 GPU 恢复异常、未知 POST 或 attempt 超限,实验停止,按现有 fail-closed 处理;不得为 A/B 提高 attempt 上限。
**数据留存:** 只存摘要、判定与时间码;不在公开 Issue 存原始私有 prompt、截图、凭据。
**禁止:** 用合成夹具、ffprobe 通过、VBench 类自动指标替代人工评审;自动指标最多排序候选供人工看。

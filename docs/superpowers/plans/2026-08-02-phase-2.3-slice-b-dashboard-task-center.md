# Phase 2.3 Slice B — Dashboard and Task Center Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Task Center placeholder with real durable-queue data, expose truthful Worker availability, provide safe cancel/retry actions, and publish a new native-Windows prebuilt candidate.

**Architecture:** Mac Core remains the only source of truth. It adds a read-only Worker status contract but does not start a Worker. Windows adds a focused Worker state store and a Task Center presentation layer over existing task snapshots and REST actions. Unsupported execution remains visibly unavailable rather than simulated.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, SQLite, pytest, .NET 10, C# 14, WPF, PowerShell 5.1, GitHub Actions `windows-2025`.

## Global Constraints

- Base commit: `58c2bc2ea900dc8ca72a1628e47f1a079a50b344`.
- Branch: `feature/phase-2.3-slice-b-dashboard-task-center`.
- Do not modify `main` or install/compile on the user PC.
- Do not auto-start a Mac Worker or execute historical queued tasks.
- Do not fabricate progress, ETA, results, approval counts or Worker health.
- Cancel is allowed only through the existing Mac Core state machine.
- Retry creates a child task only for Failed/Cancelled records.
- All new code uses aligned Chinese comments.
- Every production change follows RED → GREEN → regression → commit.

- The historical Queued-task problem maps to Worker status plus `等待执行器` display.
- Task actions reuse existing state-machine endpoints; no direct SQLite editing is introduced.
- Worker execution is intentionally excluded, so old tasks cannot begin unexpectedly.
- Missing endpoints fail closed for Legacy 2.2.
- Every new user-visible state is derived from real Mac Core data.
- No TODO/TBD placeholder remains.

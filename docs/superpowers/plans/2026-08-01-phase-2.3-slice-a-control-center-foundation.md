# Phase 2.3 Slice A — Control Center Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the capability-aware Windows Control Center shell, preserve the proven 2.2 connection/event path, and publish machine-checkable Connector/Handoff contract fixtures without implementing later-phase runtimes.

**Architecture:** Extend Mac Core with a backward-compatible capability response and versioned contract exports. Extract Windows connection/task synchronization into focused stores and a coordinator, then host existing real data in a new WPF shell with explicit capability-driven empty states.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, pytest, JSON Schema Draft 2020-12, .NET 10, C# 14, WPF, PowerShell 5.1 compatibility, GitHub Actions `windows-2025`.

## Global Constraints

- Base commit: `4ef2634ec24666d8995874d44bbf5b0e238d450a`.
- Execute in an isolated worktree created from `feature/phase-2.3-control-center-design`.
- Do not modify `main`, publish, merge, install software, or change the user’s Windows system.
- Preserve the 2.2 API, Credential Manager target, event sequence semantics, installer and rollback path.
- Do not implement Connector runtime, Media Worker, Handoff export, Dev Broker or Provider Adapter.
- Do not display fake project, progress, result, health or Provider data.
- All new code uses clear, aligned Chinese comments.
- Extend the existing zero-third-party-package Windows smoke harness.
- Unsupported native verification is reported as `not_run`.
- Each task ends with focused tests and a commit.

public enum SequenceApplyResult

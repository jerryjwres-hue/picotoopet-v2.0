# Phase 2.3 Slice B — Mac Core Delta Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build architecture-specific, offline-installable Mac Core Slice B delta packages that expose the Worker status contract while preserving the existing database, Keychain token, port, LaunchAgents and rollback path.

**Architecture:** GitHub Actions builds a pure project wheel plus a complete dependency wheelhouse on native macOS arm64 and Intel runners. The user package creates a new version directory and new virtual environment from the currently working Python 3.12 interpreter, installs only from the bundled wheelhouse, verifies the new API before activation, atomically switches the `current` symlink, and restarts only the existing user LaunchAgent. No Worker runtime is installed or started.

**Tech Stack:** Python 3.12, uv-build, pip wheelhouse, FastAPI, pytest, POSIX shell, launchctl user agents, GitHub Actions `macos-15` arm64 and `macos-15-intel` x64.

## Global Constraints

- Base commit: `e748d65fbf8a9bcc01c3c802a0b3357793b389a3`.

- Package paths and script filenames use ASCII.

- [ ] **Step 4: Implement preflight and staged installation**

The installer must:

1. verify manifest and tar payload hashes;
2. require an existing `current/.venv/bin/python` reporting Python 3.12;
3. read the existing port without changing it;
4. record the current target in `previous-version.txt`;
5. create `versions/<version>-<arch>`;
6. use the existing interpreter to create a new venv;
7. install only from bundled wheels:

```bash
"$new_version/.venv/bin/python" -m pip install \
  --no-index \
  --find-links "$package_root/payload/wheelhouse" \
  "picotoopet-core==2.3.0.dev1"
```

8. start the candidate on loopback with a temporary port and temporary runtime root;
9. verify `/api/v1/health`, `/api/v1/capabilities`, and authenticated `/api/v1/workers/status`;
10. stop the candidate;
11. switch `current` only after all candidate checks pass;
12. restart only `gui/$UID/com.picotoopet.mac-core`;
13. verify the existing configured endpoint;
14. on any post-switch failure, restore the previous symlink and restart the old service.

The token must be read through the existing Keychain lookup and never written to stdout or reports.

- [ ] **Step 5: Implement verify and rollback commands**

Verify checks:

```text
health.status == ok
capabilities.features.worker_status == true
capabilities.features.local_worker == false
workers.status.state == not_deployed
workers.status.available == false
```

Rollback switches to the target stored in `previous-version.txt`, restarts the user agent, verifies health, and never deletes the failed version automatically.

## Plan Self-Review

- The package is offline on the user Mac: all project and dependency wheels are built in native CI.
- arm64 and Intel artifacts are separate and tested on matching GitHub-hosted macOS runners.
- Activation occurs only after candidate health, capabilities and Worker status checks pass.
- The database, results, logs, token, configured port and health supervisor are not replaced.
- Rollback changes only the user-level `current` symlink and restarts the existing user agent.
- No Worker runtime, queue lease consumer, Provider, upload, payment, firewall or system service change is included.
- No TODO, TBD or unspecified implementation placeholder remains.

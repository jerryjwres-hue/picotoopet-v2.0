# PicotooPet Autonomous Intelligence and Storage Design

## Status

Approved product direction: PicotooPet becomes the single daily control surface. Windows is the human-facing control center; Mac Core remains the source of truth; Mac Worker and fixed capability providers perform execution. The Mac must remain useful when the user, Windows PC, Claude Code, Codex, and web GPT are all unavailable.

This document freezes the architecture before implementation. It deliberately does **not** replace the existing Windows WPF application, Mac Core queue, Result Store, Research Gateway, Maotai Browser Bridge, or Maotai pet component.

## 1. Product goal

Build a 7x24 autonomous research and production-support system that can:

1. accept high-level human goals from PicotooPet;
2. create safe autonomous discovery goals when no human task is waiting;
3. search, crawl, collect, deduplicate, rank, cluster, and analyze data on the Mac;
4. use `gpt-oss:20b` continuously for bounded language-understanding jobs rather than unrestricted agent loops;
5. use Crawl4AI, the existing Research Gateway toolchain, and Maotai Browser Bridge as capability providers;
6. spend Claude Code / Codex membership capacity only on high-value supervision, difficult analysis, workflow repair, and engineering work;
7. create compact, source-traceable handoff packages for the user to give to web GPT;
8. aggressively control Mac storage by deleting disposable data, compressing useful completed data, and preserving the minimum evidence needed for auditability and future reasoning;
9. reserve a stable output contract for the future ComfyUI / AI-video production system.

The primary operational requirement is:

> The autonomous Mac pipeline MUST continue useful work without Claude Code, Codex, web GPT, or the Windows PC. Those systems may improve quality or throughput, but none may become a required dependency of the baseline autonomous loop.

## 2. Frozen system boundary

The existing source-of-truth boundary is preserved:

```text
PicotooPet Windows WPF
        |
        | goals / controlled commands / status reads
        v
      Mac Core
   Queue + Result Store + Audit
        |
        v
      Mac Worker
        |
        +--> Research Gateway --> fixed search/crawler adapters
        +--> Local Ollama (`gpt-oss:20b`)
        +--> Storage lifecycle jobs
        +--> Handoff builder
        +--> Expert Broker --> Claude Code / Codex when justified
```

Rules:

- Windows never becomes a crawler or general shell executor.
- Mac Core remains the canonical task/result/audit fact source.
- Mac Worker executes only explicitly registered task types.
- Legacy Maotai OS 4.1 SQLite is **not** imported as a second source of truth.
- Legacy Maotai OS 4.1 UI is not embedded as a second daily application surface.
- Existing useful 4.1 logic may be migrated into focused capability modules after contract tests are written.
- Account writes, posting, comments, DMs, likes, follows, purchases, profile changes, login bypass, or CAPTCHA bypass remain outside autonomous scope.

## 3. Single-user interaction model: Goal Center

PicotooPet should stop exposing internal pipeline steps as the primary workflow. The Windows UI should eventually present high-level goals such as:

- 研究一个产品
- 发现值得研究的新产品
- 找消费者痛点 / 卖点
- 分析竞品
- 找最近大家喜欢看的内容
- 做主题 / 趋势分析
- 生成 AI 视频研究交接包
- 持续跟踪已有项目
- 重新分析已有数据

The user may also enter a free-form goal, for example:

> 研究这个产品，然后找最适合 TikTok 的内容方向，并生成给网页 GPT 的 AI 视频交接包。

The Mac converts the goal into bounded work units. The user should not need to manually click keyword generation, collection, analysis, opportunity generation, and handoff steps.

## 4. Goal and work-unit model

A durable `Goal` is distinct from an executable queue task.

Minimum conceptual fields:

```text
goal_id
origin: human | autonomous | system
intent_type
priority_class: P0 | P1 | P2 | P3 | P4
status
created_at
updated_at
parent_goal_id (optional)
constraints
budget_class
pinned
```

A deterministic planner expands a Goal into explicitly registered work units. The local model may suggest bounded next actions but cannot directly invent arbitrary shell commands, task types, or providers.

### Priority classes

- **P0** — urgent human task; preempts lower-priority autonomous work.
- **P1** — normal explicit human task.
- **P2** — recurring / monitored goal previously approved by the user.
- **P3** — autonomous research/discovery generated by the system.
- **P4** — maintenance, compaction, indexing, health checks, cleanup.

P0/P1 always outrank autonomous work. P3/P4 must be pausable and resumable.

## 5. Autonomous Operations Manager

A new deterministic orchestration layer runs on Mac and is responsible for:

- filling the queue when human work is absent;
- respecting priority and resource limits;
- generating autonomous discovery candidates;
- selecting the next safe workflow step;
- deciding when a research loop has reached its stop condition;
- scheduling storage compaction and cleanup;
- deciding whether an Expert Broker request is justified;
- recording every generated goal and decision into Mac Core facts.

It does **not** directly crawl, call arbitrary processes, or write external accounts.

### Useful Work Guarantee

When no P0/P1/P2 work exists, the manager tries useful P3 work in this order:

1. validate high-scoring discovery candidates;
2. continue unfinished research with missing evidence;
3. run Content Radar exploration;
4. update monitored topics/products whose freshness window expired;
5. consolidate knowledge and evidence graphs;
6. build pending handoff packages;
7. retry safe transient failures;
8. run storage compaction, deduplication, index maintenance, and tool health checks.

If no useful work remains, the Mac may reduce load. The design goal is continuous useful production, not artificial 100% utilization.

## 6. Tool-first, model-second execution

The system must exploit strong tooling and avoid asking the 20B model to solve tasks that deterministic software can solve reliably.

### Deterministic / tool work

Prefer code or tools for:

- URL normalization and deduplication;
- hashes and exact duplicate detection;
- timestamps and date filtering;
- engagement ranking and growth calculations;
- source-policy checks;
- repeated-topic frequency;
- content-size limits;
- database queries;
- scheduling and priority;
- storage accounting;
- retry/backoff;
- source availability and health;
- content-addressed artifact reuse.

### Local model work

Use `gpt-oss:20b` for bounded language tasks:

- classify relevance;
- label topic clusters;
- extract structured claims;
- identify pain points / positive drivers / audience signals;
- compare a small evidence batch;
- judge whether evidence is sufficient;
- propose a small number of next research queries;
- summarize already-validated evidence;
- compress findings into handoff-ready text.

Every model job should use a narrow role and structured result contract. Primary roles:

- `Scout` — classify candidate relevance / novelty.
- `Filter` — reject noise and low-value language content.
- `Analyst` — interpret a bounded evidence set.
- `Judge` — assess evidence sufficiency and contradictions.
- `Editor` — compress validated findings without inventing facts.

The model must return evidence identifiers with claims. Invalid structured output is retried within a bounded policy, then downgraded to `model_review_failed`; it must not silently become fact.

## 7. No unrestricted autonomous LLM loop

The 20B model may not run an open-ended ReAct-style loop that can indefinitely create work. The deterministic manager owns the loop.

A deep-research workflow stops when either:

- information gain is below **5% for two consecutive research rounds**, or
- the workflow reaches **3 deepening rounds** after the initial collection,

unless a human P0/P1 goal or a high-value Expert review explicitly extends it.

This protects time, storage, network load, and model context.

## 8. Research Priority Score

Autonomous candidates use a 0-100 Research Priority Score:

```text
Trend velocity       20
Audience resonance   20
Novelty              15
Business relevance   15
Evidence quality     10
Cross-platform       10
Actionability        10
```

Programmatic metrics should provide as much of the score as possible. The local model only supplies semantic judgments that cannot be computed safely.

Default actions:

- **85-100**: may auto-create a P3 deep-research Goal.
- **70-84**: run cheap/shallow validation only.
- **0-69**: retain as a low-cost signal; do not deep-research automatically.

Human goals do not require this threshold.

## 9. Content Radar

Content Radar is the primary autonomous discovery subsystem for “what people currently like to watch / discuss”. It is not a simple popularity leaderboard.

Pipeline:

```text
broad search/discovery
-> metadata normalization
-> exact/near dedupe
-> cheap relevance filter
-> engagement/velocity scoring
-> topic clustering
-> local-model semantic labeling
-> cross-platform corroboration
-> high-value evidence sampling
-> topic insight
-> optional deep research
```

The system tracks at least:

- absolute popularity;
- recent velocity;
- recurrence across creators;
- cross-platform recurrence;
- comment/audience resonance when available;
- common hooks;
- duration / structure patterns when available;
- saturation vs. novelty;
- reusable creative pattern rather than only individual viral items.

The intended output is a topic/pattern such as “宠物拟人上班短剧情 + 前3秒冲突 + 主人视角反转”, not merely a URL list.

## 10. Research Gateway and Crawl4AI

Crawl4AI is integrated behind the existing Research Gateway boundary as an explicitly registered read-only crawler capability. It must not be called directly from Windows.

Recommended capability family:

```text
research.search
research.fetch
research.crawl
research.deep_crawl
research.extract
```

Provider selection remains deterministic and policy-aware. Example order:

```text
official API / structured source
-> search providers
-> ordinary fetch/extract
-> Crawl4AI / Scrapling deep extraction
-> Mac browser automation when safely available
-> Maotai Browser Bridge only when a real browser session is required
-> user attention as last resort
```

Crawl4AI unavailability degrades a task to another registered provider or a waiting/deferred state; it may not crash the autonomous manager.

## 11. Maotai Browser Bridge

Maotai Browser Bridge is preserved and converted from a user-operated primary workflow into a capability provider.

Use it only when the source genuinely requires a browser session or page state not available to ordinary crawlers.

If Windows is offline:

- browser-dependent work becomes `WAITING_CAPABILITY`;
- unrelated Mac work continues;
- the overall research Goal is not marked failed unless browser evidence is mandatory and the deadline expires.

Future Mac-browser execution may be added behind the same capability contract; it must not change Mac Core as source of truth.

## 12. Legacy Maotai OS 4.1 migration policy

The uploaded 4.1 system contains reusable concepts and algorithms:

- autonomous acquisition;
- adaptive collection intervals;
- information-gain scoring;
- source policy;
- keyword discovery;
- browser capture parsers/protocol;
- local evidence preparation;
- AI task handoff rules;
- cache cleanup planning.

Migration rules:

1. migrate focused algorithms and provider adapters, not the whole application;
2. write new contract tests against PicotooPet interfaces before porting behavior;
3. never run the old SQLite database as a second live truth source;
4. old 4.1 data may be imported through an explicit one-way importer later;
5. old 4.1 UI becomes archival/compatibility material, not a daily control surface.

## 13. Expert Broker: Claude Code and Codex

Claude Code and Codex are scarce expert supervisors. They are not the autonomous engine and are never required for baseline completion.

### Claude Code default role

Use for high-value semantic supervision such as:

- research-strategy review;
- evidence contradiction review;
- finding missing counter-evidence;
- diagnosing why a high-value research goal has low confidence;
- reviewing autonomous-policy quality from summarized run telemetry.

### Codex default role

Use for high-value engineering supervision such as:

- crawler/adapter failures that appear systemic;
- queue/workflow defects;
- test-backed repairs in an isolated worktree;
- automation implementation after a design/repair decision is already bounded;
- CI / packaging / integration debugging.

### Expert request gate

An automatic expert request is permitted only when all are true:

1. task value score is **>= 90**;
2. the problem cannot be solved cheaply by one additional deterministic/local-model pass;
3. expected expert output changes a decision, prevents substantial repeated waste, or fixes a systemic issue;
4. the local Expert Budget Broker has capacity.

Conservative initial local budget:

- maximum **2 automatic expert jobs per rolling 5 hours**;
- maximum **6 automatic expert jobs per day total** across Claude Code and Codex;
- rate-limit or login failure causes an automatic cooldown and `expert_review_deferred` state.

These are local spending guards, not claims about provider plan quotas, and are configurable later.

If expert capacity is exhausted, the baseline Mac pipeline continues. The affected result is marked with its actual confidence and review status.

Experts may not autonomously merge production branches, publish releases, delete protected evidence, modify external accounts, or bypass approval/security gates.

## 14. Web GPT role

Web GPT is the user's primary high-capability reasoning/creative engine **while the user is online**. PicotooPet does not automate the consumer web session.

The autonomous Mac system prepares a compact ZIP handoff so web GPT receives curated evidence rather than raw crawl noise.

Minimum handoff contents:

```text
00_README_直接拖给GPT.md
01_GOAL.json
02_EXECUTIVE_BRIEF.md
03_VALIDATED_FACTS.json
04_EVIDENCE.md
05_SOURCE_MANIFEST.json
06_AUDIENCE_INSIGHTS.md
07_CONTENT_PATTERNS.md
08_OPPORTUNITIES.md
09_CREATIVE_BRIEF.md
10_CONSTRAINTS.md
11_EXPERT_REVIEW.md          # only if expert review exists
WEB_GPT_MASTER_PROMPT.txt
```

### Fixed Web GPT master prompt contract

`WEB_GPT_MASTER_PROMPT.txt` must contain a versioned fixed prompt with this intent:

> 你现在是 PicotooPet 生产链中的最高级推理与创意生产节点。先完整读取本交接包中的 GOAL、VALIDATED_FACTS、EVIDENCE、SOURCE_MANIFEST、AUDIENCE_INSIGHTS、CONTENT_PATTERNS、OPPORTUNITIES、CREATIVE_BRIEF、CONSTRAINTS，以及存在时的 EXPERT_REVIEW。不要重新假装抓取数据，不要伪造来源、评论、数量、价格、测试结果或产品能力。把“已验证事实”“基于证据的推断”“纯创意设计”明确分开。先检查资料之间是否存在矛盾或证据不足；发现问题时指出具体 evidence/source id，而不是凭感觉否定。然后围绕 GOAL 完成最高质量的分析和创作。若目标涉及 AI 视频，至少输出：核心传播结论、目标受众、创意方向排序、最终选择依据、完整脚本/剧本、逐镜头分镜、每镜头画面描述、角色动作、镜头运动、环境、构图、光线、对白/旁白、音效/音乐意图、首尾帧与跨镜头连续性约束、角色/产品一致性约束、负面提示词，以及可直接供图像生成和视频生成系统消费的结构化 Prompt。事实必须能回溯到交接包；创意可以大胆，但不得把创意写成事实。最后输出一个“可回导 PicotooPet”的结构化生产摘要，方便后续 ComfyUI/视频系统使用。

The implementation should version this prompt and include the prompt version in the handoff manifest.

## 15. Future ComfyUI production boundary

The current design does not integrate the user's ComfyUI production application yet, but the handoff return contract must reserve a future production package containing concepts equivalent to:

```text
story
characters
shots
image_prompts
video_prompts
audio_plan
continuity
negative_prompts
source_handoff_id
```

Future ComfyUI integration must enter PicotooPet as another explicit capability provider/workflow, not as an unrelated second control center.

## 16. Resource scheduling and conflict prevention

Initial safe concurrency defaults:

- heavy local LLM inference: **1** concurrent job;
- global crawler jobs: **4** concurrent jobs;
- per-domain crawler jobs: **1** concurrent job;
- browser-session capture: **1** per browser profile;
- P3/P4 work is preemptible by P0/P1.

The scheduler may lower concurrency when memory, swap, load, thermal pressure, or disk pressure is high. It may not increase beyond configured hard ceilings without an explicit configuration change.

## 17. Storage lifecycle: required behavior

Storage management is part of the product, not an optional cleanup script.

The local model may classify value or propose cleanup candidates, but **the model never directly deletes files or database evidence**. A deterministic Storage Lifecycle Manager owns deletion and compression.

### Data classes

#### HOT

Active task inputs and recently captured raw data.

- uncompressed while actively needed;
- never deleted during an active task;
- default raw-crawl hot window: **72 hours** after successful extraction/commit.

#### WARM

Completed useful data that may still be revisited.

- structured text, metadata, evidence snippets, model outputs, and provenance are retained;
- bulky raw text/HTML is compressed with a standard archive such as gzip after the hot window;
- duplicate copies are not retained once canonical content-addressed storage is verified.

#### COLD

Older useful research evidence.

- keep compact structured facts, source URL, capture time, content hash, key evidence excerpts, and analysis links;
- keep compressed canonical text when it materially supports future re-analysis;
- do not keep redundant downloaded representations solely because they once existed.

#### DISPOSABLE

Examples:

- exact duplicate payloads after canonical hash verification;
- temporary crawler files;
- failed partial downloads;
- regenerated caches;
- transient screenshots not referenced by evidence;
- downloaded video/audio after transcript/metadata/keyframe extraction succeeds and the raw media is not explicitly pinned or needed for production;
- obsolete extraction intermediates after downstream commit is verified.

Default disposable grace period: **24 hours** after the verified downstream artifact exists. Exact duplicate bodies may be removed immediately once the canonical referenced copy is verified.

### Minimum evidence that must survive cleanup

For any fact used in a retained result or handoff, preserve at least:

```text
source_id
source_url or stable source locator
captured_at
source_type
content_hash
relevant text/evidence excerpt or compact canonical content
evidence_id
links to derived signal/insight/result
```

If this minimum evidence does not exist, the raw source may not be deleted merely to save space.

### Large media policy

For crawled/downloaded video or audio used only for research:

1. extract metadata;
2. extract transcript/captions when available;
3. preserve selected keyframes only when useful;
4. commit hashes and evidence links;
5. after successful verification plus the 24-hour grace period, remove the bulky raw media unless it is pinned or explicitly required by a future production task.

This is a major storage-saving mechanism for 7x24 Content Radar.

### Logs and handoff packages

- durable audit facts and manifests are not treated as disposable logs;
- verbose tool/debug logs are compressed after **24 hours** and deleted after **14 days** unless referenced by an unresolved incident;
- unpinned final handoff ZIPs retain the latest **10 per Goal** and any package newer than **180 days**;
- pinned handoffs are retained until the user unpins/deletes them.

### Disk pressure modes

Normal mode requires no action while both conditions are healthy.

**Pressure mode** starts when either:

- free disk space is below **15%**, or
- free disk space is below **50 GB**.

Actions:

- immediately clean verified DISPOSABLE data;
- compress eligible WARM data;
- stop new large P3/P4 media downloads;
- reduce crawler concurrency;
- continue P0/P1 work if it can do so safely.

**Critical pressure mode** starts when either:

- free disk space is below **10%**, or
- free disk space is below **25 GB**.

Actions:

- pause nonessential P3/P4 acquisition;
- run deterministic cleanup/compaction first;
- do not delete protected evidence or pinned artifacts;
- surface a clear storage warning in PicotooPet status.

### Cleanup transaction safety

A file/artifact is deletable only if all relevant checks pass:

```text
not pinned
not referenced by an active task
not the sole preserved evidence for a retained claim
replacement/derived artifact verified
content hash/provenance recorded when required
retention/grace policy satisfied
```

Every cleanup run records a plan, removed item count, reclaimed bytes, errors, and reason. Cleanup must be idempotent.

## 18. Knowledge consolidation

Instead of repeatedly asking the model to reread old raw sources, completed research is converted into a compact evidence graph:

```text
Source -> Evidence -> Signal -> Topic -> Insight -> Opportunity
```

Claims retain evidence IDs. New research can reuse existing evidence when freshness and source-policy requirements allow.

This is both a quality mechanism and a storage/context-saving mechanism.

## 19. Nightly / unattended operation

A typical unattended cycle may perform:

```text
Content Radar exploration
-> discovery scoring
-> broad search
-> Crawl4AI / registered crawling
-> deterministic dedupe/ranking
-> local-model filtering
-> deep research for high-score candidates
-> evidence sufficiency judgment
-> knowledge consolidation
-> handoff package generation
-> disposable cleanup / warm compression
-> nightly work report
```

The Windows UI later shows a concise “茅台昨夜做了什么” report rather than raw logs.

## 20. Failure behavior

- Individual provider failure does not fail the autonomous manager.
- Missing Crawl4AI produces provider degradation/fallback.
- Windows/Browser Bridge offline produces `WAITING_CAPABILITY` only for browser-dependent work.
- Ollama unavailable pauses local-language tasks and records degraded health; deterministic work may continue.
- Claude/Codex unavailable or budget-exhausted produces `expert_review_deferred`; baseline work continues.
- Invalid model JSON never becomes a trusted result.
- Storage cleanup errors are recorded and retried safely; they do not justify deleting unverified files.

## 21. Security / approval boundary

Autonomous mode may read, search, crawl allowed sources, summarize, classify, analyze, create local files, compress local artifacts, and schedule internal work.

It may not autonomously:

- post/comment/message/follow/like;
- purchase/order/pay;
- change external account/profile settings;
- bypass authentication or CAPTCHA;
- upload protected user data to cloud models without the existing approval boundary;
- merge/release production code;
- delete protected or pinned evidence outside deterministic retention policy.

## 22. Implementation decomposition

This architecture is intentionally split into independently testable slices rather than one giant implementation plan.

### Slice A — Autonomous foundation + local model + storage + basic handoff

Deliver a Mac-only baseline that works without Claude/Codex/Windows:

- durable Goal records / autonomous candidate records;
- priority scheduler P0-P4;
- deterministic autonomous work loop;
- bounded Ollama structured jobs;
- storage lifecycle / compression / pressure modes;
- evidence-preserving cleanup;
- fixed versioned Web GPT handoff prompt and basic ZIP builder;
- restart/resume behavior.

This is the first implementation slice.

### Slice B — Research expansion + Crawl4AI + Content Radar

- register Crawl4AI behind Research Gateway;
- provider health/fallback;
- broad content discovery;
- programmatic popularity/velocity metrics;
- topic clustering and local-model labeling;
- information-gain stop rules.

### Slice C — Maotai OS 4.1 capability migration + Browser Broker

- migrate selected keyword/source-policy/autonomous algorithms;
- migrate Browser Bridge as an on-demand provider;
- add optional one-way legacy data importer;
- no second live database.

### Slice D — Expert Broker

- Claude Code supervisor provider;
- Codex engineering provider;
- local expert budgets, cooldown, audit;
- no dependency on expert availability.

### Slice E — Windows Goal Center / nightly report

- simplified Goal entry;
- suggested goals;
- active autonomous work status;
- “昨夜茅台做了什么” summary;
- expert/storage status without exposing internal pipeline complexity.

### Slice F — Production return / future ComfyUI bridge

- structured web-GPT return package;
- validation/import into Mac Core;
- explicit future ComfyUI production capability contract.

## 23. Slice A acceptance criteria

Before Slice A is considered complete, automated tests and Mac verification must prove:

1. the Mac creates useful autonomous P3/P4 work when no human task exists;
2. a P0/P1 task preempts lower-priority autonomous work without losing resumable state;
3. baseline autonomous work never requires Claude Code or Codex;
4. bounded local-model structured output is validated before becoming a result;
5. research loops obey stop limits rather than running forever;
6. storage cleanup never removes pinned data, active-task inputs, or sole evidence for a retained claim;
7. verified disposable data is actually deleted and reclaimed-byte accounting is correct;
8. useful completed text artifacts are compressed after policy allows it;
9. disk pressure mode reduces/pauses low-priority large acquisition before protected evidence is endangered;
10. Mac Core remains task/result/audit source of truth;
11. a versioned Web GPT handoff ZIP can be produced with source manifest and fixed prompt;
12. restart recovery resumes durable work without duplicating terminal results.

## 24. Non-goals for Slice A

Slice A does not:

- redesign the Maotai pet animation component;
- integrate the user's ComfyUI application yet;
- automate a consumer web GPT session;
- provide external-account write actions;
- replace the existing Research Gateway;
- merge the old 4.1 GUI into Windows;
- depend on Claude Code/Codex availability;
- bypass existing product release/asset gates.

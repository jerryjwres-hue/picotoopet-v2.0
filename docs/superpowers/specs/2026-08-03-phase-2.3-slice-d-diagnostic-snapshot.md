# Phase 2.3 Slice D — Diagnostic Snapshot End-to-End

状态：待用户书面复核的冻结设计
分支：`feature/phase23-slice-d-diagnostic-snapshot`
堆叠基线：`fix/phase23-task-center-run-binding-oneway` at `7c962fa80b55811df13d15b0e084818bdd50e054`
目标设备：Mac Core + Apple Silicon M4 Worker + Windows 11 Control Center

## 1. 目标

在不扩大云端、项目目录或模型执行范围的前提下，交付第一条真实、可见、可取消、可重试、可回滚的本地任务闭环：

```text
system.diagnostic_snapshot
```

用户能够在 Windows Control Center 创建任务，Mac Core 幂等入队，Mac Worker 安全领取并生成有限、非敏感的诊断 JSON，Mac Core 原子持久化结果，Windows 实时观察状态并读取结果。

本切片以稳定性优先。任何崩溃、无界等待、取消失效、租约错误、历史任务被领取、安装失败无法恢复或结果越权读取，均阻止发布包交付。

## 2. 明确非目标

本切片不实现：

- 项目目录、项目详情或工作区扫描；
- 日志正文采集或日志上传；
- 文件系统清单、用户文档、照片、媒体或业务数据采集；
- Token、Credential Manager 内容、环境变量值、IP、MAC 地址或设备序列号采集；
- Provider、模型、互联网访问、云端上传或费用调用；
- 历史 `analysis` 任务执行、迁移、重排或状态修正；
- 多任务并发执行；
- 通用插件任务、动态处理器发现或任意 Python 导入；
- 启用 Windows“结果”一级导航；
- 公共正式签名发布。

## 3. 现有能力复用

Slice D 必须在现有 Slice B/C 架构上增量实现：

- Mac Core 为事实源和控制平面；
- SQLite 为任务、attempt、事件、Outbox 和结果元数据事实源；
- Worker 为独立进程，只领取显式支持的任务类型；
- 现有租约、心跳、所有权终态、取消和重试状态机继续生效；
- 现有 `results` 表和 `tasks.result_id` 字段作为结果元数据关联；
- Windows 继续通过 Mac Core API 与事件流观察状态；
- 安装包继续使用预编译、版本目录、双指针和可验证回滚。

不得为本任务另建第二套队列、第二套结果数据库或 Windows 本地事实缓存。

## 4. 任务合同

### 4.1 任务类型

固定任务类型：

```text
system.diagnostic_snapshot
```

Worker 显式注册表最终只包含：

```text
system.noop
system.diagnostic_snapshot
```

`analysis` 及其他未注册类型不被领取，不被自动失败，不被自动迁移。

### 4.2 创建请求

Windows 通过受限的 Mac Core 创建接口提交固定合同。用户不能编辑任意 JSON。

规范化 payload：

```json
{
  "schema_version": "1.0",
  "sections": [
    "core",
    "worker",
    "queue"
  ]
}
```

约束：

- `schema_version` 仅允许 `1.0`；
- `sections` 必须是上述值的无重复子集；
- Windows 默认提交三个 section；
- 空 section、未知 section、额外字段和超长请求均以 4xx 拒绝，不入队；
- `cloud_policy=local_only`；
- `resource_tag=system-diagnostic`；
- `priority=50`；
- `max_attempts=2`；
- `timeout_seconds=30`；
- idempotency key 由 Windows 每次显式创建动作生成；网络重试复用同一 key；
- 活动任务去重键固定为 `system-diagnostic-snapshot-active`，在同一 Mac Core 实例上只允许一个活动诊断任务；
- 去重只检查现有活动状态，不阻止终态任务之后创建新任务。

### 4.3 状态流

正常路径：

```text
Queued → Running → Completed
```

用户取消路径：

```text
Queued → Cancelled
Running → Cancelled
```

租约恢复路径：

```text
Running → Retrying → Queued → Running → Completed|Failed
```

处理器确定性失败或硬超时直接进入 `Failed`，不自动重复执行同一潜在故障。用户可从 `Failed` 或 `Cancelled` 显式创建子重试任务。

Worker 失去租约、任务已取消或租约过期后，禁止写入结果或覆盖终态。

## 5. 诊断结果合同

### 5.1 允许内容

结果只允许包含：

- `schema_version`；
- `generated_at`，UTC ISO 8601；
- `core.version`；
- `core.health_state`；
- `core.database_schema_version`；
- `worker.worker_id`；
- `worker.state`；
- `worker.reason`；
- `worker.supported_task_types`；
- `worker.last_heartbeat_at`；
- `queue.counts`，按公开任务状态聚合数量；
- `queue.oldest_queued_age_seconds`，无排队任务时为 `null`；
- `checks`，固定检查项的 `pass|warn|fail` 和稳定 reason code；
- `warnings`，固定枚举的非敏感提示。

### 5.2 禁止内容

结果中禁止出现：

- 任意 Token、Authorization、Cookie、密码或 Credential 内容；
- 用户名、Home 绝对路径、项目路径、文件名或文件清单；
- 数据库记录正文、任务 payload、错误堆栈或日志正文；
- IP、MAC 地址、局域网扫描结果；
- Provider 名称、密钥、费用或模型请求；
- 历史 `analysis` 任务的 payload、错误正文或结果正文。

队列聚合只能输出计数和最老排队年龄，不输出任务 ID 列表。

### 5.3 大小和确定性

- UTF-8 JSON；
- 规范化键顺序；
- 最大 64 KiB；
- 结果必须通过严格 Pydantic 模型验证；
- 超过大小上限或模型验证失败时任务受控失败，不落半成品；
- 相同事实快照允许时间字段不同，其余字段保持稳定。

## 6. 结果持久化

### 6.1 原子边界

Worker 处理器只返回内存中的 `HandlerResult`，不得直接更新任务终态。

`QueueRepository.complete_leased_with_result(...)` 在同一 SQLite 事务中完成：

1. 验证任务仍为 `Running`、租约所有者匹配且未过期；
2. 插入 `results` 元数据；
3. 更新 `tasks.result_id`；
4. 更新当前 `task_attempts` 为 `Completed`；
5. 更新任务为 `Completed` 并清除租约；
6. 追加不可变 `task_events`；
7. 追加 `task.updated` 与 `result.created` Outbox 事件。

任何一步失败则整个事务回滚，任务不得出现 `Completed` 但无结果，或有结果但任务仍 `Running`。

### 6.2 结果正文存储

诊断 JSON 使用内容寻址对象存储：

```text
<data_root>/objects/sha256/<first-two>/<sha256>.json
```

写入流程：

1. 在同一文件系统的临时目录写入；
2. `flush` 并关闭；
3. 计算 SHA-256 和大小；
4. 验证 JSON 模型与 64 KiB 上限；
5. 使用原子 rename 放入内容寻址路径；
6. 再进入 SQLite 结果提交事务。

如果 SQLite 提交失败，未引用对象可由后续保守清理任务处理；本切片不自动删除任何既有对象。

`results.object_hash` 保存 SHA-256，`manifest_json` 保存不含敏感数据的类型、大小、媒体类型和校验信息。

## 7. Worker 执行和防卡死

### 7.1 单任务模型

- Worker 保持单任务串行；
- 不引入线程池或并行处理器；
- 心跳线程只续租，不执行诊断采集；
- 处理器注册表仍为封闭映射；
- 每次领取前先把满足条件的 `Retrying` 任务按状态机转换为 `Queued`，再执行类型过滤领取；
- 重排过程写入事件和 Outbox，不静默修改状态。

### 7.2 超时

`system.diagnostic_snapshot` 硬超时为 30 秒。

实现必须使用可控子进程执行该处理器，而不是仅依赖同进程计时器：

- 父 Worker 持有租约并续租；
- 子进程只接收经过验证的最小请求、只读 SQLite URI 和 Worker 状态文件路径；
- 子进程不访问网络，只能在专用临时目录写候选 JSON；
- macOS 上以独立进程组启动子进程；
- 30 秒到达后父进程向整个进程组发送终止信号并等待最多 5 秒；
- 仍未退出则强制结束整个进程组；
- 任务进入 `Failed`，错误码 `WORKER_TASK_TIMEOUT`；
- 临时候选文件被清理；
- Worker 回到可继续轮询的 `online/idle`，不能永久停留在 executing。

### 7.3 取消

- Queued 取消由 Mac Core 原子转换为 `Cancelled`；
- Running 取消也由 Mac Core 原子转换为 `Cancelled`、清除租约并发布任务事件和 Outbox；
- 父 Worker 在子进程执行期间至少每 1 秒读取任务当前状态；
- 观察到 `Cancelled`、所有权丢失或租约失效后，终止整个子进程组并删除候选结果；
- Worker 不再尝试提交第二次取消终态，也不写结果；
- 从用户确认取消到子进程退出的目标时间不超过 10 秒；
- 取消与完成竞态由数据库事务决定唯一终态，失败一方收到所有权或状态拒绝。

### 7.4 异常

错误分类固定为：

- `DIAGNOSTIC_PAYLOAD_INVALID`；
- `DIAGNOSTIC_COLLECTION_FAILED`；
- `DIAGNOSTIC_RESULT_INVALID`；
- `DIAGNOSTIC_RESULT_TOO_LARGE`；
- `WORKER_TASK_TIMEOUT`；
- `WORKER_LEASE_LOST`；
- `WORKER_TASK_CANCELLED`；
- `RESULT_PERSIST_FAILED`。

用户可见错误消息使用稳定中文摘要，不含路径、堆栈或原始异常正文。原始异常仅进入脱敏本地日志。

## 8. Mac Core API

新增或完善以下受认证接口：

```text
POST /api/v1/tasks/system-diagnostic-snapshot
GET  /api/v1/tasks/{task_id}
POST /api/v1/tasks/{task_id}/cancel
POST /api/v1/tasks/{task_id}/retry
GET  /api/v1/tasks/{task_id}/result
```

要求：

- 创建接口不接受任意 `task_type`；
- 所有接口沿用设备 Token 鉴权；
- 结果接口只允许读取与任务关联的 `system.diagnostic_snapshot` 结果；
- 结果不存在时返回明确 404/409，不返回空成功；
- 最大响应 64 KiB；
- 所有错误使用现有稳定错误合同和 trace ID；
- OpenAPI 合同、Python 模型和 Windows C# 合同保持一致；
- 创建、取消、重试和结果创建均写 Outbox 事件。

## 9. Windows Control Center

### 9.1 任务中心动作

任务中心增加一个明确按钮：

```text
创建系统诊断快照
```

按钮规则：

- Mac Core 离线时禁用并显示原因；
- Worker 未部署或不支持该任务类型时禁用并显示原因；
- 已有活动诊断任务时禁用，避免重复创建；
- 点击后立即禁用，防止双击；
- 请求完成或受控失败后恢复；
- 网络超时采用同一 idempotency key 重试，不产生重复任务。

### 9.2 状态观察

任务行继续显示真实队列状态，并对诊断任务显示：

- 排队中；
- 执行中；
- 已完成；
- 已取消；
- 失败；
- 重试中。

事件流为首选，断流时使用有上限的轮询恢复：

- 初始 1 秒；
- 指数退避到最多 10 秒；
- 总观察窗口 2 分钟；
- 超过窗口只显示“仍在后台运行”，UI 不阻塞、不自旋；
- 用户可继续切换其他页面。

### 9.3 结果查看

任务完成且存在 `result_id` 时，任务中心右侧详情区域显示“查看诊断结果”。结果内容仍留在任务中心，不启用“结果”一级导航。

固定卡片：

- Core；
- Worker；
- Queue；
- Checks；
- Warnings。

不得使用任意 JSON 动态控件直接渲染未知字段。未知字段忽略并记录本地脱敏警告；缺少必填字段显示任务中心内的安全错误状态，不导致 Shell 崩溃。

### 9.4 取消与重试

- Queued/Running 任务显示“取消任务”；
- 取消操作需要一次明确确认，但不属于外部系统审批；
- Failed/Cancelled 任务显示“创建重试任务”；
- 重试创建子任务，不重开原终态记录；
- 所有按钮有请求中状态和超时恢复；
- 页面异常继续由 `NavigationContentHost` 隔离。

## 10. 数据流

```text
Windows 创建动作
  → Mac Core 验证固定请求
  → SQLite 幂等创建 Queued + Outbox
  → Worker 类型过滤后领取
  → 子进程采集最小诊断
  → 父 Worker 校验结果、大小、取消和租约
  → 对象存储原子写入
  → SQLite 原子关联 Result + Completed + Outbox
  → Windows 事件流/有界轮询观察 Completed
  → Windows 按 task_id 在任务中心读取固定结果合同
```

任何中间失败都必须得到明确任务状态；不允许无限 `Running`、静默空白或 UI 永久等待。

## 11. 测试策略

### 11.1 RED 顺序

生产代码前必须依次加入失败测试：

1. Worker 注册表尚不支持 `system.diagnostic_snapshot`；
2. 历史 `analysis` 任务与新任务并存时，只领取新任务；
3. 处理器结果未持久化导致 Completed 无 result；
4. 结果事务中途失败时必须完全回滚；
5. 结果超过 64 KiB 时受控失败；
6. 子进程卡住时 30 秒硬超时并恢复 Worker；
7. Running 取消终止子进程且无结果；
8. 完成/取消竞态只产生一个终态；
9. Retrying 任务未重排为 Queued 时无法再次领取；
10. Windows 双击创建只产生一个任务；
11. Windows 事件流断开后有界轮询，不冻结 Dispatcher；
12. 结果缺字段或未知字段不使页面崩溃；

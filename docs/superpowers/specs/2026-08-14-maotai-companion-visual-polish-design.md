# 茅台陪伴型视觉优化设计

## 目标

把现有轻量茅台互动组件从“功能成立”提升到“看起来像正式产品的一部分”，同时维持当前安全边界：只调整 WPF 表现层，不修改 Core、Worker、任务执行、队列、Provider、持久化或发布逻辑。

## 已确认方向

采用“陪伴型”布局，而不是把茅台做成首页主角，也不把它缩成普通状态图标。

- 右侧区域保持为辅助区，宽度目标约 300–320px。
- 茅台主体视觉尺寸目标约 260–280px，根据实际素材透明边界微调。
- 茅台应明显可见，但不能压过首页的任务卡、标题和新建任务入口。
- 继续使用现有高质量 PNG 位图素材，不切换为廉价矢量占位风格。

## 视觉调整范围

本轮只处理以下内容：

1. 茅台在右侧栏中的大小、上下留白和视觉重心。
2. 气泡的圆角、阴影、内边距、文字层级和按钮比例，让它更像角色自然说话，而不是系统弹窗。
3. 鼠标经过、点击、呼吸和工作状态的动作幅度，让动画更自然、更克制。
4. 茅台与“系统状态”卡之间的间距，避免右侧栏拥挤。
5. 必要时把右侧栏从当前 280px 轻微放宽，但不改变首页左侧任务区的结构和业务绑定。

## 不做的事情

- 不重做首页布局。
- 不新增网页、WebView、Rive、Spine 或其他重型运行依赖。
- 不修改任务状态来源和任务业务逻辑。
- 不增加新的 AI 后台调用。
- 不增加持续高频动画或高 CPU 占用效果。
- 不为了视觉效果改动 Core、Worker 或安装架构。

## 交互保持

现有第一版交互继续保留：

- 待机轻微呼吸和微动作。
- 鼠标经过时轻微跟随。
- 点击后显示茅台气泡。
- 气泡继续复用现有“新建任务”和“看看进度”入口。
- 根据首页已有任务计数切换待机/工作表现。
- 偶尔出现低频主动提示。

本轮只优化这些表现的视觉质感，不扩大功能范围。

## 安全边界

茅台继续作为独立 WPF `UserControl`。宿主只向它提供已有展示状态和计数；组件只返回现有快捷入口事件。任何素材加载、动画或气泡展示异常都必须局部降级，不能扩散到主程序。

如果视觉调整导致组件加载失败，预期结果仍然是“茅台不显示或停止自身动画”，而不是影响首页、任务流程或程序启动。

## 验证要求

完成视觉优化后必须重新通过：

- 茅台 WPF smoke：控件可实例化、位图可加载、首页可承载。
- Windows contract/security tests。
- 历史 WPF 回归验证。
- WPF solution warnings-as-errors build。
- Published Control Center self-test。
- Windows 正式安装包构建与安装/升级/恢复/回滚生命周期验证。

只有上述验证保持通过，才认为本轮视觉优化完成。

## 完成标准

最终效果应满足：

- 第一次打开首页时，茅台看起来像 Picotoo Pet 自带的角色，而不是临时贴上去的图片。
- 右侧栏层级清楚：茅台是陪伴角色，“系统状态”是信息卡，两者互不抢占。
- 动画肉眼可感知但不过度活跃。
- 气泡精致、简洁，不产生系统默认控件的廉价感。
- 不引入新的主程序稳定性风险。

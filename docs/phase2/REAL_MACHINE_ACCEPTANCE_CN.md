# Picotoo Pet V2 Phase 2 双机实机验收标准

## 验收原则

本阶段不是以“界面能打开”作为完成标准，而是验证双机控制链在真实局域网中的速度、耐久性、可恢复性和使用体验。不得通过关闭审计、降低 SQLite 耐久等级、丢弃关键事件、删除错误处理或减少冻结功能来换取延迟数字。

## 标准验收环境

性能主验收使用：

- Mac mini M4 Pro 64GB；
- Windows 11、RTX 5070 Ti 16GB；
- 两台设备连接同一路由器或交换机；
- 优先使用千兆或更高有线网络；
- Mac Core 地址 `192.168.1.161:8766`；
- Windows 地址由 DHCP 或固定配置提供；
- 测试期间不执行模型下载、视频渲染或大型系统更新。

Wi-Fi 必须可用并具备自动恢复，但物理无线干扰导致的偶发抖动需与程序处理延迟分开记录。

## 自动验收项目

双击 `VERIFY_PHASE2_WINDOWS.vbs` 后，验证器默认执行 500 次 REST、500 次任务提交与事件回传、500 个 Ping/Pong 样本，并必须输出：

- `schema_version`
- `generated_at`
- `status`
- `environment.base_url`
- `environment.machine`
- REST Health 的 count、p50、p95、p99、max
- WebSocket Ping/Pong 的 count、p50、p95、p99、max
- 任务提交耗时
- 任务创建到对应事件回传耗时
- 首条和末条样本任务 ID
- 最后确认事件序号
- 错误数组

缺少安装、设备令牌或版本文件时必须输出 `incomplete`，不能伪造通过。连接失败、认证失败、超时和数据格式错误必须输出不同的机器错误信息。

## 性能硬门槛

有线千兆环境：

| 指标 | p95 | p99 |
|---|---:|---:|
| `GET /api/v1/health` | ≤ 50 ms | ≤ 100 ms |
| WebSocket Ping/Pong | ≤ 50 ms | ≤ 120 ms |
| `POST /api/v1/tasks` 确认 | ≤ 80 ms | ≤ 150 ms |
| 创建任务到 Windows 收到对应事件 | ≤ 150 ms | ≤ 300 ms |

界面体验：

- 点击创建任务后 100 ms 内出现“正在提交任务”反馈；
- 正常页面切换 p95 不高于 200 ms；
- UI 线程不得执行网络请求或同步日志写盘；
- 任务列表必须使用虚拟化、容器复用和增量更新；
- 连续快速点击不得产生重复提交；
- 后台错误不得使窗口无响应。

## 一致性验收

执行以下测试，每项要求任务丢失为 0、重复业务结果为 0：

1. 创建任务时拔掉 Windows 网线。
2. Mac 已提交任务但 Windows 未收到响应时断网。
3. WebSocket 断开后恢复网络。
4. Windows 睡眠 60 秒后唤醒。
5. 重启 Mac Core。
6. 重启 Windows Desktop。
7. 重复发送相同 `Idempotency-Key`。
8. 重放已经确认的事件序号。
9. 事件队列暂时积压超过 UI 消费速度。
10. SQLite 发生短时 Busy。

通过条件：

- SQLite 中任务状态与 Outbox 一致；
- 重连从 `last_sequence` 之后补发；
- 旧事件不能回滚新状态；
- 同一任务行被增量更新，而不是每次清空列表；
- 认证失败显示“认证失败”，不能被覆盖为普通离线；
- 所有用户可见错误包含可定位的错误摘要和日志位置。

## 断线恢复门槛

- 连接异常识别不超过 2 秒；
- 首次重连尝试不超过 500 ms；
- 网络恢复后 p95 在 5 秒内恢复在线；
- 断线期间 Mac 已入队任务在恢复后可见；
- 旧 WebSocket 消费者必须被取消并等待退出，不能同时存在两个状态写入者；
- 应用退出后不得遗留持续重连进程。

## 安全验收

- Token 只存在于 Windows Credential Manager；
- `settings.json`、安装报告、性能报告和日志中没有明文 Token；
- 日志对 Bearer 和长令牌形态自动脱敏；
- 安装、升级和回滚不访问 Protected 业务目录；
- 本阶段不具备云端上传能力；
- 测试任务只写 Mac Core 自身 SQLite 队列；
- 程序版本切换前后均验证 SHA-256。

## 稳定性验收

第一轮通过性能门槛后进行 8 小时 Soak Test：

- 桌面程序持续在线；
- 每分钟执行一次 Health；
- 每 5 分钟创建一条验收任务；
- 每小时模拟一次 10 秒网络中断；
- 记录进程私有内存、句柄数、线程数和 WebSocket 重连次数。

通过条件：

- 进程意外退出 0 次；
- 未恢复连接 0 次；
- 任务丢失 0；
- 重复结果 0；
- 内存不存在持续单向增长；
- 句柄不存在持续单向增长；
- 日志写入不阻塞 UI；
- SQLite 完整性错误 0。

## 验收结论规则

只有以下条件同时成立才标记 Phase 2 第一纵向切片为通过：

1. Python/Mac Core 全套自动测试通过。
2. Windows 项目在 .NET 10 Release 模式编译成功且警告为 0。
3. Core Smoke Test 返回 `PHASE2_CORE_SMOKE=PASS`。
4. 安装报告为 `pass`。
5. 实机验证 JSON 为 `pass`。
6. 有线局域网 p95/p99 达标。
7. 断网和重连测试无任务丢失或重复副作用。
8. 8 小时 Soak Test 无泄漏趋势和进程退出。

任一项失败时必须保留报告、Trace ID、错误类型和日志，不得把失败项写成“基本可用”后进入下一阶段。
